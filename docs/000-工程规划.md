## 1. 背景与定位

### 1.1 一句话定位

**以 AAR 形式发布的、Android 版 `uv` 命令行可执行**——Rust 交叉编译（官方 tier2 target
`aarch64-linux-android`）的 `libuv_cli.so`（arm64-v8a，exec 型 PIE），单文件自包含、
无 assets；TLS 走 rustls 自带根证书。终端里由 node-pty 经 `forkpty` + `execve` 启动，
与 `aosp-python-cli` 组合成完整 python 工具链（uv 管环境与包，解释器来自 python-cli）。

### 1.2 为什么需要它

- 原生 Android 没有 python，更没有 uv；`uv` 是当前事实上的 python 环境/包管理快线
  （venv 创建、锁文件式安装、`uv pip` 兼容层），终端场景需要**独立进程**的真 `uv` 命令；
- uv 本体是 Rust 单二进制、无动态数据树——是五条 CLI 线里最贴合"exec 型单文件"形态的一条
  （与 python-cli 的 assets 物化、node-cli 的 npm 树物化相比，零运行期物化步骤）；
- 上游**无 Android 官方产物** ⇒ 一律 CI 源码自建（C2 纪律：不下载上游二进制，构建期也不引入）。

### 1.3 边界（在范围 / 不在范围）

| 在范围内 | 不在范围内 |
|---|---|
| `libuv_cli.so` 的 Rust 交叉编译、C 依赖试编探针、exec 门禁、AAR 打包、发布 | python 解释器本体（属 aosp-python-cli）；任何嵌入 API / NAPI（exec 型独立进程） |
| 版本事实源 `uv-cli.lock.json`（独立 semver；含 §8 依赖 sha 记录设计） | venv/环境组合引导（属消费方/环境引导层——本文件只定义**契约**：§7 环境注入 + §7.1 探针） |
| 与 python-cli 的组合环境契约（`UV_PYTHON` 等注入，D7） | git 二进制（git 依赖源属 aosp-git-cli；运行期 PATH 组合即可） |
| CI 真实流水线 + GitHub Release 先行 / Maven Central 随后（§9/§10.1） | managed python 下载（`uv python install`）：C2 红线，见 §7 已知限制 |

## 2. 版本规则

- 制品版本 = **uv 上游版本，独立 semver**，与 node 系无配对（无 NODE_MODULE_VERSION 约束）；
- 升级 = lock 增项 + CI 重新构建（镜像 pty 的 release 纪律）；
- **uv 发版频繁**——跟随节奏独立于 python-cli（python-cli 升版不触发本仓重建，反之亦然）；
  跟随成本评估见 §11 R4；
- 版本钉选（2026-11-03 M1 开工实测）：**uv 0.13.6**（官方最新稳定版；draft 0.9.0 作废回写）。
  PINS/fetch 脚本、`CLI_VERSION`、lock draft 条目已同步；首产后 lock 回写事实。

## 3. 总体架构与关键决策

```
┌─ 消费方 App 进程 ─────────────────────────────────────────────────┐
│  环境引导层（bridge 载荷或 Kotlin）                                 │
│   - 注入 PATH / LD_LIBRARY_PATH / UV_PYTHON / UV_CACHE_DIR /       │
│     XDG_CACHE_HOME / HOME / TMPDIR（§7 表）                        │
│   - UV_PYTHON ← aosp-python-cli 物化产物（组合契约 D7）             │
│        │ pty.spawn(<nativeLibraryDir>/libuv_cli.so, …)             │
│        ▼                                                           │
│  uv 子进程（exec 型，独立生命周期；forkpty → setsid → TIOCSCTTY）   │
│   - TLS：rustls 编译期内嵌根证书；缓存/venv 全部落 filesDir         │
└───────────────────────────────────────────────────────────────────┘
```

### 3.1 关键决策记录（不可回归项）

| # | 决策 | 理由 | 反面（禁止） |
|---|---|---|---|
| **D1** | **exec 打包 `useLegacyPackaging=true`** | exec 要求物理落盘 `nativeLibraryDir`（targetSdk≥29 SELinux 禁止从 filesDir exec；不落盘 `execve` ENOENT） | `useLegacyPackaging=false`（dlopen 库口径，与本仓相反） |
| **D2** | **版本 = uv 上游版本，独立 semver** | 无 ABI 约束；python/git/pnpm 同口径 | 与 runtime/node 配对（无必要） |
| **D3** | **一律 CI 源码自建**（源码 tarball + Cargo.lock） | 上游无 Android 官方产物；C2（不下载可执行代码，构建期同纪律） | 拉取上游任何平台二进制改名复用 |
| **D4** | **TLS = rustls 自带根证书**（编译期内嵌根集，禁用系统证书目录探测） | Android 无 `/etc/ssl/certs`；单二进制自包含 | 依赖系统证书目录 / `SSL_CERT_FILE`（那是 python-cli 侧的 pip 口径，与 uv 无关） |
| **D5** | **`libc++_shared.so` 不随包**——由消费方包内 node-runtime 供给 + `LD_LIBRARY_PATH` 注入 | exec 子进程走默认 linker namespace 看不到 App 库目录；同 App 内重复供给会包内冲突（provision BANNED 同款纪律） | 本 AAR 自带 libc++_shared.so（消费方真实无 node-runtime 场景另拍板，先改本文件，§4.4） |
| **D6** | **命名 `libuv_cli.so`**（`_cli` 后缀统一纪律） | Android 打包只认 `lib*.so`；命名禁区：`libuv.so`（与 libuv 库混淆）、`libnode.so`（引擎占用） | `libuv.so` / 任何无 `_cli` 后缀命名 |
| **D7** | **组合契约：解释器来自 python-cli，本仓不内嵌 python** | 一仓一版本线、职责单一；python-cli 已解决静态扩展 + stdlib 随包 | uv 内嵌 python / `uv python install` 下载 managed python（运行期下载可执行 = C2 红线，且上游构件非 Android 形态） |

## 4. 构建设计（M1 核心）

### 4.1 工具链与源钉选

| 项 | 取值 | 说明 |
|---|---|---|
| uv 源 | `github.com/astral-sh/uv/releases/download/<ver>/source.tar.gz`（实测资产名；规划模板原写 `uv-<ver>.tar.gz`，以 0.13.6 实测为准），SHA-256 校验（官方 `.sha256` 边车核对） | fetch 不改源；交叉编译参数经 cargo 配置 / RUSTFLAGS 注入；版本钉选见 §2 |
| Cargo 依赖 | tarball 内 `Cargo.lock` 钉版 + crates.io 拉取（CI 缓存）；依赖 sha 记录粒度 ⬜（§8 两方案 M1 拍板） | 可复现性 = rust 版本 + `Cargo.lock` + lock.builtFrom 记录；CI 构建一律 `--locked` |
| rust 工具链 | rustup stable（版本钉进 lock.builtFrom.toolchain.rustVersion）+ `rustup target add aarch64-linux-android`（官方 tier2，rustup 直接装 std，无需自建） | 工具链版本是可复现性输入，与 uv 版本同等钉选 |
| linker 接线 | 首选 cargo-ndk；备选 `.cargo/config.toml`：`[target.aarch64-linux-android] linker = "aarch64-linux-android24-clang"`（NDK llvm prebuilt 入 PATH） | 两路径等价；M1 以 cargo-ndk 先行，失败退 config.toml 并回写本文件拍板主口径 |
| NDK | 与 aosp-node-runtime 对齐（r28c 或更高）⬜ | 一台 runner 一条 NDK 线；lock.builtFrom.ndk 记录 |
| 16KB 页 | `RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384"` | 16KB 页设备硬要求；门禁 ⑦ 强制 |
| strip | `llvm-strip --strip-unneeded`（NDK 自带） | 体积治理第一手段；⬜ 体积量级见 §4.2 要点 |
| TLS 栈 | rustls + 编译期内嵌根证书（webpki-roots 口径），禁用系统证书目录探测（D4）；crypto provider（ring / aws-lc-rs）⬜ 以 M1 实际依赖树与试编结果定（§4.3） | Android 无系统证书目录；`rustls-native-certs` 在 Android 上的行为不依赖 |
| C 依赖 | ring（预生成 arm64 汇编 + cc）/ zstd-sys（cc 编 vendored C 源）等 | M1-T1 试编探针，见 §4.3——**本工程最大新工** |

### 4.2 交叉编译流程（build-uv-cli-android.sh，M1 实现）

```
① env：NDK/toolchains/llvm/prebuilt/<host>/bin 入 PATH（clang/llvm-ar/llvm-strip 可寻）
② rustup：stable 工具链 + rustup target add aarch64-linux-android；
   cargo-ndk（cargo install cargo-ndk --locked，或 runner 缓存二进制）
③ cc 类依赖交叉环境：CC_aarch64_linux_android / AR_aarch64_linux_android /
   CXX_aarch64_linux_android = <toolchain>/bin/aarch64-linux-android24-clang（/llvm-ar/clang++）
   ——cc crate（ring/zstd-sys 等）的编译入口
④ RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384"
⑤ cargo ndk -t arm64-v8a --platform 24 build --release --locked
   （等价：cargo build --release --target aarch64-linux-android + config.toml linker，§4.1）
⑥ strip：llvm-strip --strip-unneeded target/aarch64-linux-android/release/uv → libuv_cli.so
⑦ BUILD-METADATA.txt / FETCH-METADATA.json（镜像 pty/python-cli 归档形态：
   rust 版本 / target / api / NDK / flags / uv 版本 / Cargo.lock sha256）
```

要点与风险：

- Android target 默认产出 PIE、经系统 linker 启动——**不靠默认假设**，门禁 ①② 以 ELF 事实
  为准，首产以 provision 输出核验 ⬜；
- **体积预估**：⬜ 25–40MB 量级（工作区方案 §3.2 口径；Rust release + strip 后），首产实测
  回填 lock；超标处置见 §11 R3；
- `--locked` 纪律：CI cargo 构建一律 `--locked`，防依赖树漂移破坏可复现；
- 产物重命名 `uv → libuv_cli.so` 在 strip 后进行（D6）。

### 4.3 C 依赖可编性探针（M1-T1，首项试编）

| 依赖 | 类型 | 风险点 | 通过判据 |
|---|---|---|---|
| ring | 预生成 arm64 汇编 + cc | NDK clang 直编是否可用 ⬜ | `cargo build --target aarch64-linux-android --locked` 通过 + 产物过 provision 全门禁 |
| zstd-sys | cc 编 vendored zstd C 源 | 多文件 C 编译 + `AR` 接线 ⬜ | 同上 |
| aws-lc-rs（**实测在树**：Cargo.lock 含 aws-lc-rs 1.18.0 + aws-lc-sys 0.44.0；uv workspace Cargo.toml 硬编码 rustls feature `aws_lc_rs`，2026-11-03） | C/汇编 + 构建系统复杂（cmake 需求口；host 无 cmake ⚠️） | Android 交叉编译已知繁琐 | 同上；不通过则 provider=ring（feature 裁剪属构建配置非改源，§13，先回写本表再实施） |
| 其余 `*-sys`（lzma 等）⬜ | cc | 以 Cargo.lock 实际清单为准逐个过 | 同上 |

方法：M1 首轮直接在 uv 依赖树上 `cargo build --target aarch64-linux-android --locked` 试编；
失败输出（汇编/链接错误）如实记录回写本文件。

**降级路径（如实设计，不静默）**：

- crypto provider 可切换：rustls 支持 ring / aws-lc-rs 二选一——一颗试编失败即切另一颗
  （feature / provider 配置注入，不改源）⬜ 可行性随试编定；
- 压缩/归档类 sys 依赖失败 → uv feature 裁剪（`--no-default-features` + 手选 features）⬜
  裁剪集试编后定；功能受限（如部分压缩格式支持降级）在 README/Release notes 如实上报；
- 任一降级都先回写本文件再动实现；降级不影响 exec 门禁与发布纪律本身。

### 4.4 `libc++_shared.so` 供给决策（D5）

- **事实更新（2026-11-03 CI 首产实测）**：DT_NEEDED = `[libdl.so, libm.so, libc.so]`——**不含
  `libc++_shared.so`**（本构建形态静态链 C++ 运行时；v1.0 的「动态链常态」预判被实测推翻，⬜ → ❌，
  此行保留为决策史）。⇒ 消费方**无需**为 uv 注入 `LD_LIBRARY_PATH`；lock `matrix.allowedNeeded`
  登记 libc++_shared.so 保留（白名单放宽无害）；P6 反证探针改为记录性（003 test-cases TC-003-12b）。
- 决策：**不随包**（本 AAR jniLibs 仅 `libuv_cli.so`）⇒ 供给方 = **消费方包内 node-runtime**
  （同 App 各 AAR 的 native 库汇聚到同一 `nativeLibraryDir`）；lock `matrix.allowedNeeded`
  已登记该库、provision `BANNED_IN_AAR`（libnode.so）同款「不重复供给」纪律；
- 运行期：exec 出的子进程走默认 linker namespace，须消费方注入
  `LD_LIBRARY_PATH=<nativeLibraryDir>`（工作区方案 §2 次级约束）；本仓消费方文档必须写明
  该运行期依赖（§7 表已列）；
- **替代方案（记录备查，⬜）**：NDK clang 支持 `-static-libstdc++`（链 libc++_static.a，
  工作区方案 §2 同款表述）——若 M1 试编可行且 16KB/门禁全过，可免除运行期
  LD_LIBRARY_PATH 依赖；是否切换须先改本文件拍板；
- 开放问题（v1.0 遗留）：消费方不引 node-runtime 的场景 ⬜——彼时要么本 AAR 自带
  libc++_shared.so（jniLibs 白名单扩展 + provision 同步扩展），要么切静态链；
  需求真实出现再拍板。

## 5. 制品形态与打包投放（AAR）

```
uv-cli-<ver>.aar
└── jni/arm64-v8a/libuv_cli.so    # exec 型 PIE（ET_DYN + PT_INTERP=/system/bin/linker64，16KB 对齐）
```

- 本仓**无 assets**（与 python-cli 最大差异：uv 是自包含单文件可执行；缓存/venv 全部
  运行期落 filesDir，不随包、不物化）；
- 打包：**`useLegacyPackaging=true`**（D1）；模块只作 AAR 容器，无任何 Kotlin/Java 源；
- `META-INF/uv-cli.properties`（provision 生成）：tool.version / abi / name / size /
  sha256 / provisionedAt；
- jniLibs 纪律：仅 `libuv_cli.so`；禁入 `libnode.so`（provision `BANNED_IN_AAR`）与
  `libuv.so`（命名禁区，D6）；
- Maven 阶段发布前检查（runbook §4）：provision `--check` 全过 + lock `status=released`。

## 6. exec 型门禁 profile

| 门禁 | 判据 | 与 pty（dlopen 库）门禁的差异 |
|---|---|---|
| ELF 形态 | `ET_DYN`（PIE） | 同 |
| 解释器 | **PT_INTERP 恰 1 个且 = `/system/bin/linker64`** | **相反**（pty 要求 PT_INTERP=0） |
| 依赖 | **DT_NEEDED 白名单**（系统库 + lock `matrix.allowedNeeded` 登记，含 `libc++_shared.so` 但不随包） | pty 是"必须含 libnode.so" |
| NAPI | 无门禁 | pty 有"napi_* 未定义引用"门禁 |
| 页对齐 | 16KB（`-Wl,-z,max-page-size=16384`） | 同 |
| 出处 | sha256 / size / 源版本 / NDK / rust 工具链 / flags | 同 |

- **已实现（M0）**：provision 全套 exec 门禁（退出码 0/2/1；`--inspect` / `--out` / `--check`；
  draft 只记录不比对；`--allow-page-align-4k` 仅 bring-up）；jniLibs 兄弟文件检查
  （仅 `libuv_cli.so`）；
- **M1 新增需求：无**（本仓无 assets ⇒ 无 manifest/静态性检查；无壳脚本 ⇒ 无白名单扩展）；
  M1 的工作是 CI 接线 + 门禁结果回填 lock（DT_NEEDED 实测清单、sha/size）。

## 7. 运行期契约（消费方 / 环境引导层）

| 环境变量 | 值 | 说明 |
|---|---|---|
| `PATH` | `<nativeLibraryDir>:$HOME/bin:/system/bin` | uv 直呼或经 `$HOME/bin` symlink 农场（工作区方案 §4.3，exec symlink 按目标文件标签放行） |
| `LD_LIBRARY_PATH` | `<nativeLibraryDir>` | 仅当产物 DT_NEEDED `libc++_shared.so`（⬜ §4.4 探针定）；若切静态链可省 |
| `UV_PYTHON` | `<filesDir>/python-bridge-tools/…`（python-cli 物化产物中的解释器） | **组合契约（D7）**：uv 的默认 python = python-cli；⬜ 指向形（可执行路径 vs 目录）M2 实测定 |
| `UV_CACHE_DIR` | `<filesDir>/uv/cache` | 显式钉死 uv 缓存根，防落未知处 |
| `XDG_CACHE_HOME` | `<filesDir>/cache`（uv 实际落 `<XDG>/uv` 子目录，2026-11-03 实测形态） | XDG 兜底（uv 及其他工具） |
| `HOME` / `TMPDIR` | filesDir 子目录 | venv / 临时文件；Android 无 `/tmp` |
| `SSL_CERT_FILE` | —（不注入） | uv TLS 走 rustls 内嵌根证书（D4），与 python-cli 侧 pip 的 CA 各自独立 |

- venv 布局：`<filesDir>/uv/venvs/<name>/{bin/, lib/python<ver>/site-packages/, pyvenv.cfg}`；
  `bin/python` 系 uv 生成的 symlink → 基解释器（`nativeLibraryDir` 内 `libpython_cli.so`；
  exec symlink 的 SELinux 只查目标文件标签 `apk_data_file`，放行——工作区方案 §4.3）；
  ⬜ 真机核验（P2/P4）；
- **已知限制（消费方文档必须写明）**：
  1. `uv python install` / managed python **禁用**：运行期下载可执行违反 C2，且上游
     python-build-standalone 构件非 Android 形态；`UV_PYTHON` 钉死后 uv 不再自行找 python；
  2. `uv pip install` sdist 不可安装（设备无编译器，python-cli 同款能力边界）；纯 wheel 域可用；
  3. git 依赖源（`uv pip install git+…` / lock 中 git 源）需 `git` 在 PATH——属
     aosp-git-cli 线的组合项 ⬜；
  4. `libc++_shared.so` 运行期供给依赖消费方含 node-runtime（§4.4）。

### 7.1 回程探针（M2 验收判据，真机）

| # | 探针 | 判据 |
|---|---|---|
| P1 | `pty.spawn(libuv_cli.so, ['--version'])` | 版本串回程、exit/close 齐全 |
| P2 | `uv venv <filesDir>/uv/venvs/t1` | venv 落 filesDir、`pyvenv.cfg` 生成；venv 内 python symlink 可用性 ⬜ 记录事实 |
| P3 | `uv pip install <纯py包>`（如 `packaging`） | HTTPS（rustls 内嵌根证书生效）+ 安装进 filesDir venv site-packages |

## 8. 唯一事实源：`uv-cli.lock.json`

镜像 pty/node-cli 纪律：版本 + 大小 + sha256 + 门禁 + 出处，二进制不入库。当前唯一 release
为 **draft**（`0.9.0` 计划版本；size=0、sha256 空；androidApi=24；门禁七项布尔位）——draft
不伪造哈希，首个真实 CI 构建后回写并以实际钉住的 uv 版本为准。

**lock 扩展字段设计（v2.0 新增，M1 回写时落地；现 draft 的 `builtFrom.toolchain` 为单句
prose、`flags` 为 TBD）**：

```jsonc
"builtFrom": {
  "source": "uv <ver> source tarball (github.com/astral-sh/uv releases), unmodified",
  "toolchain": {                       // 结构化扩展（M1 落地）
    "rustVersion": "<rustup stable 钉版>",
    "cargoNdk": "<cargo-ndk 版本>",
    "target": "aarch64-linux-android",
    "api": 24
  },
  "cargoLockSha256": "<tarball 内 Cargo.lock 整文件 sha256>",
  "cargoDeps": [ { "name": "ring", "version": "…", "sha256": "…" } ],  // 粒度 ⬜ 见下
  "tls": "rustls + bundled roots（provider/根证书来源以实测为准 ⬜）",
  "ndk": "…", "flags": "-C link-arg=-Wl,-z,max-page-size=16384; strip"
}
```

**依赖 sha 记录粒度（⬜ M1 拍板，两方案）**：

- 方案 A：`Cargo.lock` 整文件 sha256 + `cargo license` 全量许可清单随 Release 归档（轻）；
- 方案 B：逐 crate `.crate` 文件（crates.io 下载产物）sha256 全量记录（重，供应链审计口径）；
- 倾向：**A + cc 类 C 依赖（ring/zstd-sys 等）逐条记录**——编译风险与审计需求集中在
  C 依赖上；拍板后回写本文件并按新粒度回填 lock。

## 9. CI 设计（真实流水线，M1 替换 scaffold CI）

- runner：`ubuntu-24.04`；装机：NDK（与 runtime 对齐线）、JDK 21、Node 20、
  **rustup + stable 工具链 + `rustup target add aarch64-linux-android` +
  cargo-ndk（`cargo install --locked` 或缓存二进制）**、curl/file/tar；
- 步骤：resolve version（tag `v<uvver>` push 或 dispatch）→ fetch（uv 源码 tarball，
  SHA-256 校验，Cargo.lock 记录）→ C 依赖试编判据（§4.3，M1-T1 已定）→
  `cargo build --release --target aarch64-linux-android --locked`（cargo-ndk / config.toml）→
  strip → 改名 `libuv_cli.so` → provision（全门禁）→ 归档
  `uv-cli-v<ver>-android-arm64-v8a.tar.gz`（libuv_cli.so + BUILD/FETCH-METADATA +
  LICENSES + **cargo license 清单**）+ `.sha256` → GitHub Release（tag 钉 commit）→
  artifact 上传 → lock 人工回写（M4 自动化评估）；
- 缓存：cargo registry（`~/.cargo`）+ `target/`（key 含 rust 版本 + Cargo.lock sha；
  Swatinem/rust-cache 或手动 actions/cache）⬜；首轮全链时长 ⬜（量级 15–30min，实测后定
  缓存策略）；
- scaffold 配置期 CI（`config-check` + provision 退出码自检 + 脚本语法门）保留为流水线
  前置 job 或独立 job，真实流水线在 M1 并入同文件替换。
